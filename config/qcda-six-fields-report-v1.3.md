# 球场档案｜公开六项目与赛前分析报告 V1.3

生效日期：2026-10-27（北京时间）。生产模板：`public.qc_ai_report_templates` 的 `FOOTBALL_MATCH_AI_REPORT / QCDA-AI-REPORT-4C7P-20261027-V1.3`。

## 接收原始八项后的工作流

1. 读取用户提交的已确认数据，或已锁定的 `jc_model_outputs`。不得把 `jc_matches` 赛程当作已锁定预测。
2. 运行 `node scripts/qcda-six-fields-report.mjs <input.json>`，按**字段名而非①②序号**映射为网站六项：核心方向、单选倾向、官方让球、半全场、总进球、比分参考。
3. 双选保留原始范围（如主队不败＝胜和平），独立 TEST 单选所指方向排首位；若不在双选集合内则 BLOCK。官方让球及让球数、HT/FT、离散总进球、三个比分保持原序。M7/M8不公开显示。
4. 每场查看赛前事实：最近比赛与主客场表现、官方伤停停赛、排名与赛程情境、正式交锋等。缺少资料时自行查找俱乐部/联赛官方或可靠媒体，记录链接与发布日期。比赛开赛后的事实不能回填赛前报告。
5. 按**四章七段**起草完整报告；新文章的章节标题及正文统一使用核心方向、比分参考，不出现数据库/采集/收集/核验/补齐/锁板等工作语言。自然论证足球事实，不披露流程。
6. 运行 `validateReport(report,six,verifiedEvidence)` 做结构和禁词校验，逐场再人工核对证据、事实和结论。没有七段、有无证据或字段冲突时保持**待审**，不得宣称已生成/发布。
7. 除非用户明确要求写入并获得验收通过，不得覆盖任何 FINAL、已发布报告、详情快照或生产预测行。发布需要按原有后台受控流程同步详情快照。

## 验收

`node --test scripts/qcda-six-fields-report.test.mjs`

- 正例：10月27日已经锁定的原始预测，检查六字段、比分原序和单选优先。
- 反例：10月28日17场真实已发布赛程当前尚无已确认的 `jc_model_outputs`，正确状态是 `blocked/awaiting_verification`，绝不编造预测与报告。
- 禁词：报告中出现“中央数据库”“采集”“模型方向”等时直接驳回。

**边界说明：** 该校验程序负责确定性转换、搭建报告计划和质量拦截，不包含实时联网搜索或自行调用大语言模型。赛前事实主动检索和四章七段撰写由具备搜索能力的报告生成工作流负责，不能将空模板当成已经写好的分析报告。
