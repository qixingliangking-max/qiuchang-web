# 球场档案｜AI精选师 V2.0（干净重建，影子研发）

历史状态（已结束）：曾在独立分支研发，从未进入生产。

## 一、重建原因（2026-10-19核验）

上一代 V1.0—V1.2 的历史模拟不断波动。V1.2 按编号取前 N 场，是组合结构基准测试，不是有选场能力的AI；V1.1 则偏向用官方赔率隐含概率和高覆盖排名，出现“命中了仍亏损”的系统性组合问题。

对 2026-09-23—2026-10-18 共 284 场“FINAL 锁板早于开赛、最后修改早于开赛”的比赛核验发现：

- `jc_model_outputs.home_prob/draw_prob/away_prob`：**284/284 三项均未填充**。不能冒充具备已校准的胜平负模型概率。
- 官方赔率单场资料丰富，但赔率隐含概率 **不是独立模型优势**，不能拿它再判断自身预期盈利。
- `jc_match_details.feature` 开赛前采集 255/284 场；严格以**FINAL 的锁板时间**作截止，只有 **170/284** 场具备该特征快照。
- `jc_market_snapshots` 锁板时可取：HAD 243 场、半全场 HAFU 256 场、TTG 257 场、比分 CRS 257 场。
- 当前 `league_team_p2_stats`、联赛高频等如果是赛后重新计算的，不能用于早期日期回测，除非有当时的有效版本。
- 旧V1.0—V1.2冻结方案和赛果是审计证据，全部原样保留；不可删除失败样本，也不能回写历史赢家。

## 二、新体系（从输入开始重建，不再修补旧选择器）

`T0赛前快照(不可修改) → 资料质量Gate → 独立赛前概率 → 单场玩法Gate → 结构优化Gate → 人工确认 → 新版本冻结 → 赛后独立结算`

### T0冻结输入

`match_id, business_date, match_num, kickoff_at, decision_at, model_locked_at, model_updated_at, market_snapshot_ids/captured_at, feature_fetched_at, raw_inputs_hash`。

**decision_at是当次真正选场的时点**。所有数据必须 `captured/fetched/updated <= decision_at < kickoff_at`，模型须先锁板。历史没有这个时间点不能自行虚构历史发布；仅作“当时可用信息”的研究模拟。

### 第1层：概率与路径建模

- **方向**：以当时可用的球队攻防率估计进球强度，独立算出H/D/A及官方让球方向概率，和锁板模型方向做一致性核验；遇到缺失特征弃选。方向单选的“每场赔率≥2.00”保留为用户要求的**测试约束**，不作为“越高越好”的排名指标。
- **半全场**：必须有赛前半场/上下半场节奏或得失球率数据，才能输出独立的半全场联合概率；不可简单把锁板 TOP1×TOP1 当精选。
- **总进球**：由赛前独立进球分布计算0—7+球概率，明确1球低尾及4球以上高尾，2球数是否集中由模型概率决定；分布不完整拒绝。
- **比分**：用合法的比分全分布和赛前模型路径核验前2、前3，必要时结合**截止时点前**已有的联赛/主客场比分频率，检查1-1偏差与尾部；不机械选赔率最小的比分。

### 第2层：组合优化师（只算赛前可得）

分别计算候选结构的单场事件概率、选项覆盖概率、组合线数、赔率、预期返还/1元投入、组合失败风险；组合必须通过真实性、赔率和误差带Gate。不固定必须出4类；可**弃选**，并报告弃选率。

以前约定的结构暂列为对照模板：方向单×单（每场赔率≥2）、半全场单×单、总进球2×2、比分2×2 / 3×3 / 3×3×3。模板不是必然要发布的方案，若分布不给出优势则不选。

等额1000点只是可比较的**模拟结算基准**；不执行真实投注。

## 三、评价与审计纪律

- 版本V2与V1全部独立，不改旧报表。**单场预测准确率**与**整组2串1/3串1命中率**分别统计，不混用。
- 固定报告：每个玩法合格机会数、选出数、弃选数、单场覆盖、整组覆盖、赔率分布、累计模拟净值、最大回撤、连续亏损、质量Gate拒绝原因。
- 历史9/23—10/18已参与规则设计，是研发/回归样本，**不算样本外验证**。下一步只有赛前实冻的新日期才能用于证明提升。
- 不根据最终比分挑胜场、不用赛后补算联赛统计、不允许“当时没锁板”的数据参与择场、不承诺盈利或用户目标命中率。
- 阶段晋级：数据可审计→计算可复现→影子赛前记录→多批次前向验证→用户批准才切换正式精选。

## 四、实现边界

代码存放 `internal-test/selector-v2/`，仅供服务端/离线研究；浏览器不暴露数据库服务端密钥。保持正式网站、JC六项模型和Pro权限不受影响。V2训练完成前，**正式运营继续保留原发布结果，V1.2停用作候选决策但不删除回测档案**。

## 五、真实可用性审计（2026-10-19，未读取任何完赛结果）

V2代码模块：
- `asof_input.sql`：只读生成候选快照，时点为 `max(FINAL.locked_at, FINAL.updated_at)`，严格早于开赛；只选该时点前采集的赔率和赛事 `feature`。
- `adapter.cjs`：把SQL行转换成统一输入，正规化主客队方向、赔率键；阻断任何赛果字段。
- `engine.cjs`：以球队赛前得失球资料独立计算进球分布，再推导方向、总进球、比分概率；半全场无真实半场数据直接弃选；组合按相同预算计算各分支的预期返还和组合风险。**所有输出均不发布**。
- `engine.test.cjs`：9个Node内建测试样例；另完成8项独立执行检查，8项全部通过。
- `asof_coverage_audit_20261019.json` 与 `asof_coverage_audit_adapter_20261019.json`：按真实时点的数据可行性审计。

对 22 个有记录业务日的 284 场严格FINAL：
- 170 场具备该时点的全部四项攻防率和最低样本量；114 场被数据Gate拒绝。
- **仅作为未校准研究候选**，方向最多7天有候选组合，总进球1天、比分2×2两天；半全场0天，其他比分结构0天。它们均**未通过正式发布标准**。
- 旧V1.x曾发生高命中仍亏损，V2这次优先控制缺数据和无独立优势，不以日更凑场为目标。
